# World Material "Mana" 設計書

本書は World Material "Mana" の世界設定ドキュメント群の**永続的な設計指針**を定める。世界の中身そのもの（公理・定理の本文）ではなく、

- ドキュメントをどう構造化するか（分類体系・ディレクトリ構成・相互参照）
- 命題（公理・定理・未解明領域）と応用ファイルを**どう書くか**（記述規約）

を規定する。個々の命題の中身（何が存在し、何が導かれるか）は `world/core/` を、応用ファイルの中身は `world/*.md` をそれぞれ正とし、本書では中身を重複して持たない。

## 1. 本書の役割と他ドキュメントとの関係

### 1.1 ドキュメント階層

| 階層 | ファイル | 内容 | 読者 |
|---|---|---|---|
| 設計（メタ） | `docs/architecture.md`（本書） | 構造・分類・記述規約 | 執筆者・レビュアー |
| 著者の選択 | `docs/design-notes.md` | 公準的事項の集約 | 派生作品作者・執筆者 |
| 概念索引 | `glossary.md` | 全概念の索引 | 全読者 |
| 世界の本体 | `world/core/`, `world/*.md` | 公理・定理・応用 | 物語作者・興味読者（中学生〜） |

各ファイルの内部書式（design-notes.md のエントリ書式、glossary.md の章立てとタグ付けなど）は当該ファイル自体の冒頭で定義する。本書では「どのファイルに何を集約するか」までを規定する。

### 1.2 本書を変更する場合

構造・分類・記述規約（本書が規定する範囲）を変更する場合、本書を**先に更新**してから実装し、設計と実装の乖離を避ける。命題や応用ファイルの**中身**（公理・定理の命題文や内部構造、応用ファイルの記述）の改訂は `world/` を直接編集する（本書は中身を持たないため、ここでの先行更新は不要）。

### 1.3 対象読者

世界の本体（`world/` 配下）の対象読者は次のとおり。

- **物語作者**: ゲーム・小説・漫画などで本世界設定を利用する執筆者
- **興味読者**: 中学生〜の一般読者。物語から世界設定に興味を持って読みに来る人

本書はこれら 2 層の読者に向けた本体ドキュメントを生成可能にする設計とする。すなわち、専門用語に頼らず、論理構造を保ちつつ平易に書ける構造を備える。

## 2. 分類体系

世界の根本（コア体系）を支える分類は 4 種のみ。これとは別に、特定のドメイン（魔法・魔術・超能力・遺物・ダンジョン・種族・歴史等）を扱う**応用層**が `world/` 直下にフラット配置される。応用層は分類接頭辞を持たず、ファイル単位で管理する。

| 接頭辞 | 名称 | 役割 | 配置 |
|---|---|---|---|
| **E** | 公理（存在に関するもの） | 何が存在するか | `world/core/axioms.md` |
| **I** | 公理（相互作用に関するもの） | 何が起きうるか | `world/core/axioms.md` |
| **T** | 定理 | 公理から導出される世界の法則 | `world/core/theorems.md` |
| **Q** | 未解明領域 | 意図的に答えを与えていない領域 | `world/core/open-questions.md` |

数学でいう「補題」「系」は採用しない。定理から直接導かれる短い帰結は、定理本文中の**節**として配置するか、応用ファイル内の該当節に置く（各定理の本文（`world/core/theorems.md`）内で配置する）。

### 2.1 core / 応用 の振り分け原則

| 観点 | core（公理・定理） | 応用 |
|---|---|---|
| 普遍性 | どの著者が書いても同じ | 著者の選択・観察事実を含む |
| 抽象度 | 世界の根本法則 | 特定の現象・存在の記述 |
| 数の増減 | 安定 | 将来増える可能性が高い |
| 派生作品での扱い | 改変すれば別世界 | 改変しやすい・足しやすい |

「魔法・魔術・超能力」は**定義**（短い命題）は core/theorems.md に T7〜T9 として置き、**詳細**（体系・暴走・具体例）は応用ファイル（`magic.md`, `spellcraft.md`, `psionics.md`）に置く。

## 4. 記述規約

### 4.1 命題本文の標準セクション順序

公理（E/I）・定理（T）の本文は、次の順序で書く。

| 順序 | セクション | 必須 | 内容 |
|---|---|---|---|
| 1 | 命題 | ◎ | 1〜2 文で簡潔に。何が成立するか |
| 2 | 導出元 | ◎（公理は除く） | どの公理・定理から導かれるか |
| 3 | 証明スケッチ | △ | 定理のみ。導出が自明でない場合 |
| 4 | 詳細 | ○ | 命題から論理的に必然な内容、補足説明（観測事実は 1〜2 文まで。詳細は §4.6 参照） |
| 5 | 重要な帰結（節） | △ | 定理のみ。各定理の本文（`theorems.md`）内に節として配置 |
| 6 | 関連 | ◎ | 他の命題・応用ファイルへのリンク |

未解明領域（Q）は別構造（§4.5 参照）。

著者の選択（公準的事項）は本文に書かない。`docs/design-notes.md` に集約する。

### 4.2 応用ファイル冒頭の前提・関連リスト

応用ファイルは冒頭に、依存する公理・定理を明示する。

```markdown
*前提: [T7 魔法](core/theorems.md#t7-魔法), [E6 精神エネルギー](core/axioms.md#e6-精神エネルギー)*
*関連: [T5 存在強度#ビッグバン由来物質の還元不可能性](core/theorems.md#重要な帰結-ビッグバン由来物質の還元不可能性),
       [Q1 真度操作](core/open-questions.md#q1-真度を人為的に深くする方法)*
```

### 4.3 ID 付与・廃止・分割

- 各分類の末尾連番で追加（E7, I5, T10, Q7 など）
- 廃止された ID は再利用しない。ファイル内に `[廃止] T3 旧名称 — 移動先` の痕跡を残す
- 既存命題が肥大化した場合は分割記号（E3a, E3b 等）を使わず、新 ID を採番して旧 ID は廃止扱いとする
- 定理内「重要な帰結」節および応用ファイル内の節は**独立 ID を持たない**。安定したアンカー名で参照する

### 4.4 相互参照のリンク形式

| 場面 | 形式 |
|---|---|
| 同一ファイル内 | `[E1 現界](#e1-現界)` |
| `core/` 内の異ファイル | `[E1 現界](axioms.md#e1-現界)` |
| 応用 → `core/` | `[E1 現界](core/axioms.md#e1-現界)` |
| `core/` → 応用 | `[magic.md](../magic.md)` |
| 応用同士 | `[races.md](races.md)` |
| 応用ファイル内の節 | `[現化魔法](magic.md#現化魔法)` |
| 定理内「重要な帰結」節 | `[T5#ビッグバン由来物質の還元不可能性](core/theorems.md#重要な帰結-ビッグバン由来物質の還元不可能性)` |

アンカー名は GitHub の Markdown レンダリングに従う（小文字化、空白のハイフン化）。日本語見出しはそのまま使用可。

**リンク対象**: ID 付き見出し（公理 E/I・定理 T・未解明領域 Q）に限らず、応用ファイル内の任意の見出しを自由に参照してよい。

**見出し改訂時の注意**: 見出しを変更するとアンカーも変わるため、当該見出しへの被リンクが切れる。改訂時は被リンクの有無を確認する。リンク有効性の機械チェックは Phase 1 で整備するスクリプトに任せる。

**特に頻繁に参照されるハブ**: 次の節は複数ファイルから繰り返し参照されるため、改訂時の影響範囲が広い。命題本体を改訂する場合でも、節名を変えるかどうかは慎重に判断する。

- 定理内の「重要な帰結」節（例: T5 内「重要な帰結: ビッグバン由来物質の還元不可能性」、T4 内「優先結合則」、T3 内「危険性」、T2 内「特殊事例: ビッグバン」）
- 応用ファイル内の参照対象節（例: `spellcraft.md`「術式の定義」、`spellcraft.md`「ワープ」、`magic.md`「人代における魔法」）

**禁止事項**: 命題（公理 E/I・定理 T・未解明 Q）を参照する際に、コードのみ（`T1`、`[T1]`、`E4` など）の表記は使わない。必ず **セクション名を含めたリンク** で書く。

- ❌ NG: `T1`、`[T1]`、`（T7 魔法）`、本文中の「I1 により…」
- ✅ OK: `[T1 エネルギー保存則](theorems.md#t1-エネルギー保存則)`
- ✅ OK（shortcut reference 形式）: `[T1 エネルギー保存則]` を本文で使用し、ファイル末尾に `[T1 エネルギー保存則]: theorems.md#t1-エネルギー保存則` を定義

範囲・列挙も例外としない。「T1〜T6」「T1, T5, T7」のように特定の命題群を指す場合は両端または各要素をリンクで書く（例: `[T1 エネルギー保存則] 〜 [T6 ...]`）。ID 採番の説明・廃止リスト・テンプレート例示でプレースホルダーとして書く場合は、引用（`>`）またはコードブロックに入れる。

### 4.5 未解明領域の本文構造

```markdown
### [Q1] 名称

**背景**: 既知の事実と未解明部分の境界を述べる
**現在判明していること**: 観測事実、関連する組織の認知レベル
**この空白の意図**: 物語ギミック・派生作品での活用例
**関連**: 関連する公理・定理・応用ファイル
```

### 4.6 観測事実の扱い

観測事実（メカニズムは明らかでないが、現象として観察される事項）は、性質に応じて置き場所を変える。

| 観測事実の種類 | 置き場所 | 例 |
|---|---|---|
| 公理・定理の本性に近い性質 | 当該公理・定理の本文に 1〜2 文 | 原初返り（[E6 精神エネルギー] の真度分布の偏りとして） |
| 特定ドメインに紐づく現象 | 該当応用ファイル | ダンジョン内での瘴気蓄積（dungeons.md）、ケース C 道具の出現（artifacts.md） |
| 大規模で独立した現象群 | 専用の応用ファイル | 種子から発芽した各種族の特性（races.md） |
| メカニズム不明部分 | Q として登録 | 原初返りの発生メカニズム → [Q1 真度操作] |

運用ルール:

- 公理・定理の本文での言及は **1〜2 文** に留める。それを超える詳細は応用ファイルへ移し、本文からはリンクする
- メカニズム不明部分は必ず Q を立てて切り分け、本文に「謎」を抱え込まない
- 観測事実を定理に置くのは原則避ける（定理は論理的に導出されるもの、観測事実は経験的に観察されたもの）。観測される規則性が公理から論理的に説明できると判明した場合は、その時点で定理に格上げする

### 4.7 文体

- 「である」調で簡潔に
- 命題本体は 1〜2 文以内
- 詳細はリスト形式を許容（読みやすさ優先）
- 命題内で対象を指す場合は ID を併記する（例: 「個体（[E4 個体]）」）
- 中学生〜の読者を想定し、数学・論理学の専門用語に依存しない（「補題」「系」等は本文に書かない）

### 4.8 図の管理

- 図は `world/images/` に配置
- ソース（drawio 等）と書き出し（svg）の両方を含める
- キャプション・凡例は本文側に記す
- 体系の全体図は `world/README.md` に集約

### 4.9 メタ・制作情報を本文に書かない

`world/` 配下の本文（公理・定理・未解明領域・応用）および `glossary.md` は、読者（中学生〜の興味読者・物語作者）に向けた世界の記述に徹する。次の制作・運用・設計のメタ情報を本文に書かない。

- **ツール・運用**: `scripts/check.py`、`make check`、CI／ワークフロー、整合性チェックの手順
- **設計／規約／計画文書**: 本書（`architecture.md`）、`writing-rules.md`、`redesign-plan.md` への言及

これらは執筆者・レビュアー向けの情報であり、メタ文書（`docs/`）に置く。読者は本文から制作の裏側を意識せずに読み進められるべきである。

**例外**: `design-notes.md` は派生作品作者に向けた読み物であり（§1.1）、`README`（ハブ）から `design-notes.md`・本書への誘導リンクは正規の導線として許容する。ただし命題本体（`axioms.md` 等）からは `design-notes.md` を参照しない（読み物としての連続性を保つため。design-notes.md §0）。

機械チェックへの昇格候補（本文中の `scripts/`・`*.md` メタ文書名の grep 検出）だが、現状はレビュー（world-doc-reviewer 観点 C7）で確認する。

## 5. メンテナンス

### 5.1 命題の追加・改訂

**新たに公理・定理・未解明領域を追加する場合**:

1. §2 の分類に従って種別を判定
2. 該当ファイル（`world/core/` の `axioms.md`・`theorems.md`・`open-questions.md`）の末尾に追加し、最大番号 + 1 を採番（§4 の記述規約に従う）
3. glossary.md にエントリを追加（カテゴリタグ付き）
4. 既存命題からの参照リンクを必要に応じて更新
5. 影響を受ける応用ファイルの「前提」「関連」リストを更新
6. 公準的事項があれば design-notes.md にエントリを追加

> 本書（architecture.md）は命題別の節を持たないため、命題追加時に本書へ転記する手順はない。命題の中身は `world/core/` が正である。

**既存命題を改訂する場合**:

1. 命題本体（`world/core/`）を改訂する（§4 の記述規約に従う）
2. 依存する下流（応用ファイル、定理内の重要な帰結節）を全て点検
3. 命題の本質を変えない改訂では ID とアンカー名を維持する

**昇格・降格**:

| 変化 | 操作 |
|---|---|
| 未解明 → 定理 | 答えを与える場合に昇格。新 T# を採番し、Q# は「→ T# として解明」と記録して保持 |
| 定理 → 公理 | 世界の根本前提とみなされる場合に昇格（極めて稀） |
| 応用内の概念 → 定理 | 応用内で導入した概念が複数応用から参照され、世界法則として機能していると判明した場合 |

### 5.2 整合性チェック観点

レビュー時に確認する観点:

- **重複**: 既存命題と意味的に重複していないか（glossary.md で類似概念を検索）
- **分類判定**: 公理／定理／未解明領域／応用の判定が §2 に従っているか
- **導出元の妥当性**: 導出元の公理・定理から命題が論理的に導かれるか
- **波及**: 既存の定理・応用に矛盾を生じないか
- **相互参照**: 関連命題のリンクを更新したか
- **アンカー維持**: 定理内「重要な帰結」節および応用ファイル内の参照対象節のアンカーを変更していないか
- **glossary.md / design-notes.md 反映**: 新概念・公準的事項をそれぞれ反映したか
- **派生作品からの視点**: 改変ポイントが design-notes.md に明示されているか
- **物語利用者の視点**: 戦闘・能力・キャラクター設計のルールが早引き可能か
- **未来執筆者の視点**: 「これは Q# として認識されている空白か、単に書かれていない領域か」が判別可能か

### 5.3 廃止のルール

- 廃止された ID は再利用しない
- ファイル内に `[廃止] X# 旧名称 — 廃止理由・移動先` を残す
- glossary.md からは削除可能（重複防止のため）

### 5.4 新分類の追加

4 分類（E/I/T/Q）で扱いきれない命題が出てきた場合、新分類の追加は本書の改訂を伴う。安易に追加せず、まず既存分類で扱えないか検討する。
