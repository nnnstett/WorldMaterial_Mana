# 世界設定ドキュメント再構築 計画書

本書は、既存の世界設定ドキュメントを「公理 → 定理」の論理構造へ移行するための作業計画である。移行が完了したら本書はアーカイブされる。永続的な設計指針は `docs/architecture.md` に集約する。

---

## 1. 目的

既存の世界設定（`world/`, `character/`, `history/`, `glossary.md`）を再編し、次の状態に到達する。

- **論理構造の可視化**: 公理から定理が導出される形で記述され、矛盾の混入を抑制できる
- **読者層への対応**: 中学生〜の興味読者と物語作者が、それぞれ必要な深度で読める
- **派生作品の改変ポイントの明示**: 著者の選択した事項と論理的必然の事項が分離されている
- **後付け差し込み口の確保**: 「未解明領域」として体系内に明示的な空白を持つ

---

## 2. 新構造

### 2.1 分類体系

採用する分類は 4 種のみ。

| 接頭辞 | 名称 | 役割 |
|---|---|---|
| **E** | 公理（存在に関するもの） | 何が存在するか |
| **I** | 公理（相互作用に関するもの） | 何が起きうるか |
| **T** | 定理 | 公理から導出される世界の法則 |
| **Q** | 未解明領域 | 意図的に答えを与えていない領域 |

数学でいう「補題」「系」のような中間分類は採用しない。定理から直接導かれる短い帰結は、その定理の本文中に**節**として配置するか、応用ファイルの該当節に置く（§3.4）。

### 2.2 ディレクトリ構成

```
WorldMaterial_Mana/
├── README.md
├── LICENSE.md
├── glossary.md
│
├── docs/
│   ├── architecture.md          # 永続的な設計指針
│   ├── design-notes.md          # 著者の選択（公準的事項）
│   └── redesign-plan.md         # 本書（完了後アーカイブ）
│
└── world/
    ├── README.md                # 導出マップ・推奨読み順のハブ
    ├── core/
    │   ├── axioms.md            # E1-E6 + I1-I4
    │   ├── theorems.md          # T1-T9（重要な帰結は各 T 内の節）
    │   └── open-questions.md    # Q1-Q6
    ├── magic.md
    ├── spellcraft.md            # 術式の定義を冒頭で導入
    ├── psionics.md
    ├── artifacts.md
    ├── dungeons.md
    ├── races.md
    ├── timeline.md
    ├── magic-history.md
    └── images/
```

旧 `character/` `history/` ディレクトリは廃止し、内容は `world/` 直下に統合する。ファイル名は全て英字に統一する（魔法→magic, 魔術→spellcraft, 超能力→psionics, 種族→races, ダンジョン→dungeons）。

### 2.3 core / 応用 の振り分け原則

| 観点 | core（公理・定理） | 応用 |
|---|---|---|
| 普遍性 | どの著者が書いても同じ | 著者の選択・観察事実を含む |
| 抽象度 | 世界の根本法則 | 特定の現象・存在の記述 |
| 数の増減 | 安定 | 将来増える可能性が高い |
| 派生作品での扱い | 改変すれば別世界 | 改変しやすい・足しやすい |

例:
- マナ・魂・精神エネルギー → core（公理）
- エネルギー保存則・存在強度・共鳴現化 → core（定理）
- 魔法・魔術・超能力の**定義** → core（T7〜T9 として）
- 魔法・魔術・超能力の**詳細**（体系・例・暴走） → 応用
- ダンジョン・伝説の武具・種族・歴史 → 応用

## 3. 公理・定理・未解明領域の完全リスト

### 3.1 公理（存在に関するもの）

| ID | 名称 | 命題 |
|---|---|---|
| E1 | 現界 | 物理法則に従う 3 次元時空が存在する |
| E2 | 真界 | 現界とは別次元の空間が存在する |
| E3 | マナ | 真界には純粋ポテンシャルエネルギー（マナ）が存在し、あらゆる物理エネルギー・物質に変換可能である |
| E4 | 個体 | 現界には境界と持続性を持つ物質単位（個体）が、入れ子構造で存在する |
| E5 | 魂 | 個体ごとに固有の形を持つ、真界と現界の接点（魂）が存在する |
| E6 | 精神エネルギー | 思考・意思を持つ個体は、波長・強さ・方向の 3 属性を持つエネルギー（精神エネルギー）を発生させる |

### 3.2 公理（相互作用に関するもの）

| ID | 名称 | 命題 |
|---|---|---|
| I1 | 変換則 | マナが現界に現出する瞬間、必ず物理エネルギーまたは物質に変換される |
| I2 | 共鳴則 | 精神エネルギーはマナと共鳴し、マナの変換の触媒として機能する |
| I3 | 副産則 | マナの変換に伴い、対となる瘴気が発生する。瘴気は物質・エネルギーと結合してマナへ戻る |
| I4 | 作用則 | 精神エネルギーは他個体（およびその魂）にも作用しうる |

### 3.3 定理

| ID | 名称 | 導出元 | 詳細の所在 |
|---|---|---|---|
| T1 | エネルギー保存則 | I1 + I3 | theorems.md |
| T2 | 共鳴現化 | E5 + E6 + I1 + I2 | theorems.md |
| T3 | 自然現化 | I1（媒介なし） | theorems.md |
| T4 | マナ還元 | I3 + T2 | theorems.md |
| T5 | 存在強度 | E6 + I3 + T2 | theorems.md |
| T6 | 同調 | E5 + E6 + I2 + I4 | theorems.md |
| T7 | 魔法 | T2 の応用 | theorems.md（命題のみ）→ magic.md |
| T8 | 魔術 | T2 の応用（術式を介する） | theorems.md（命題のみ）→ spellcraft.md |
| T9 | 超能力 | I4 の応用 | theorems.md（命題のみ）→ psionics.md |

### 3.4 重要な帰結の配置

定理に強く結びつく短い帰結は、その定理の本文中に**節**として配置する。応用ファイルから安定アンカーで参照されるため、節名は命題本体を改訂しても維持する。

| 定理 | 配置する節 |
|---|---|
| T2 共鳴現化 | 「特殊事例: ビッグバン」 |
| T3 自然現化 | 「危険性」 |
| T4 マナ還元 | 「優先結合則」 |
| T5 存在強度 | 「重要な帰結: ビッグバン由来物質の還元不可能性」 |

応用文脈に強く結びつく帰結は応用ファイル側の節に置く。

| 帰結 | 配置 |
|---|---|
| 人代における魔法行使の困難性 | `magic.md`「人代における魔法」節 |
| ワープの魔術不可能性 | `spellcraft.md`「ワープ」節 |

### Phase 1: 整合性チェックスクリプトの整備

以降の Phase で繰り返し利用する整合性チェックスクリプトを最初に構築する。書きながら違反を早期検出することで、表現の冗長化・規則違反の蓄積を防ぐ。

- [ ] `scripts/check.py`（または同等のスクリプト）を新規作成
- [ ] 以下のチェックを実装:

  **形式**
  - [ ] **参照形式**: コードのみの参照（`T1`、`[T1]`、散文中の「T1 により」等）を禁止（`architecture.md` §4.4）
  - [ ] **リンク有効性**: 全 Markdown リンクが解決すること。具体的には:
    - 参照先のファイルが存在する
    - 参照先のアンカー（見出し）が対象ファイル内に存在する
    - リンクテキスト内の **ID コード**（`E1`, `T2` 等）と、リンク先見出しに含まれる ID コードが一致する（例: `[T1 エネルギー保存則](...#t2-...)` のような不整合を検出）

  **構造**
  - [ ] **必須セクション**: 各公理（命題・関連）、定理（命題・導出元・関連）、未解明領域（背景・現在判明・空白の意図・関連）、応用ファイル（前提・関連の冒頭行）が揃っていること
  - [ ] **ID 一意性**: E/I/T/Q ID の重複定義がないこと
  - [ ] **glossary 整合性**:
    - 全 ID（E/I/T/Q）が `glossary.md` にエントリを持つこと
    - glossary 各エントリのカテゴリタグ（`[公理 E#]`、`[定理 T#]` 等）が、命題ファイル側の分類と一致すること
    - 同一概念が複数エントリで重複定義されていないこと
  - [ ] **旧パス検出**: `world/魔法.md`, `world/dungeon.md`, `character/`, `history/` 等への参照が残っていないこと

  **内容**
  - [ ] **禁止語検出**: 本文中（コードブロック・引用を除く）に数学用語「補題」「系」、廃止接頭辞 `L#`, `C#` が現れていないこと

  **長さ・分量上限**（暴走防止。原則 error 扱い。下記「運用」参照）
  - [ ] **命題長さ**: 「命題」セクション本文が 1〜2 文に収まること（句点 `。` の数で判定）
  - [ ] **段落の文数**: 1 段落の文数の上限
  - [ ] **詳細セクションの行数**: 「詳細」「書くべき内容」等の節の行数上限
  - [ ] **箇条書きの数**: 1 つのリストの項目数上限
  - [ ] **節の階層深さ**: 見出しの深さ上限（例: H4 まで）
  - [ ] **1 命題エントリ全体の文字数**: 1 つの公理・定理・未解明エントリ全体の文字数上限。**ただし Markdown リンクの URL 部分とリンクテキスト全体は文字数カウントから除外する**（リンク先の見出し名が長い場合に誤検出されないよう）
  - [ ] **応用ファイル全体の行数**: 1 ファイルあたりの行数上限

  **その他**
  - [ ] **TODO/FIXME の散在検出**: `- [ ]`、`TODO:`、`FIXME:` 等がファイル末尾の `## ToDo` 節以外に現れていないこと

- [ ] **運用ポリシー**:
  - 長さ・分量上限は原則 **error**（critical）扱いとする。warning だと無視されるだけで暴走抑制にならない
  - どうしても上限超過が必要な場合は、対象の直前に明示的な許容コメント（例: `<!-- check:length-exempt 詳細セクション -->`）を置き、スクリプトはそれを認識して除外する。暴走と意図的超過を区別する
  - 各上限値の閾値は、**一般的に読みやすいとされる日本語文章の基準**（例: 1 文あたり 60〜80 字、1 段落あたり 5 文程度など、テクニカルライティングや日本語スタイルガイドの定石）を参考に検討する
- [ ] CI またはローカルで実行できる形にする（`make check` 等）
- [ ] 既存ドキュメント（再構築前の状態）に対して一度走らせ、ベースライン出力を把握する
- [ ] 検出ルール・閾値・例外コメントの記法は `scripts/README.md` に管理する
