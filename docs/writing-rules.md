# 執筆ルール

World Material "Mana" のドキュメントを書くときに守るルール。
概念的な土台は [`architecture.md`](architecture.md) §4 にある。本ドキュメントは
それを操作的なルール集に落としたもの。

## 1. ファイルの種別と役割

| 種別 | 場所 | 役割 |
|---|---|---|
| 核 | `world/core/axioms.md`, `theorems.md`, `open-questions.md` | 公理 E/I・定理 T・未解明領域 Q を定義する |
| 応用 | `world/*.md`（核以外） | 核を参照しつつ個別ドメインを記述する |
| 用語集 | `glossary.md` | 全 ID の一覧 |
| メタ | `docs/*.md` | 設計方針・計画・本ルール集。構造規約の適用外 |

本ルール集の §2〜§12 は **核・応用・用語集** に適用される。
メタ文書（`docs/`）は禁止語や NG 例を本文に含める必要があるため、構造・禁止語
・分量のルールは適用しない。

## 2. 応用ファイル冒頭の前提行

応用ファイル（`world/` 直下の核以外）は **冒頭 8 行以内** に依存する公理・
定理を明示する。

```markdown
*前提: [T7 魔法](core/theorems.md#t7-魔法), [E6 精神エネルギー](core/axioms.md#e6-精神エネルギー)*
*関連: [T5 存在強度#ビッグバン由来物質の還元不可能性](core/theorems.md#重要な帰結-ビッグバン由来物質の還元不可能性),
       [Q1 真度操作](core/open-questions.md#q1-真度を人為的に深くする方法)*
```

「前提」という語をヘッダ近傍に必ず含める。

## 3. 相互参照のリンク形式

### 3.1 リンクの書き方

| 場面 | 形式 |
|---|---|
| 同一ファイル内 | `[E1 現界](#e1-現界)` |
| `core/` 内の異ファイル | `[E1 現界](axioms.md#e1-現界)` |
| 応用 → `core/` | `[E1 現界](core/axioms.md#e1-現界)` |
| `core/` → 応用 | `[magic.md](../magic.md)` |
| 応用同士 | `[races.md](races.md)` |
| 応用ファイル内の節 | `[現化魔法](magic.md#現化魔法)` |
| 定理内「重要な帰結」節 | `[T5#ビッグバン由来物質の還元不可能性](core/theorems.md#重要な帰結-ビッグバン由来物質の還元不可能性)` |

アンカー名は GitHub の Markdown レンダリング規則（小文字化・空白のハイフン化・
日本語見出しはそのまま）。リンクテキスト先頭の ID と参照先見出しの ID は一致
させる。参照先のファイル・アンカーは必ず実在させる。

### 3.2 散文での参照禁止

命題（E/I/T/Q）を本文中で指すときに、コードのみ・括弧のみで書かない。
必ずセクション名を含むリンクで書く。範囲・列挙も例外ではない。

```
NG: T1 により、エネルギーは保存される
NG: マナの状態（[T1]）が安定する
NG: T1〜T6 はエネルギー保存系
NG: 対象は T1, T5, T7 である
OK: [T1 エネルギー保存則](theorems.md#t1-エネルギー保存則) により、エネルギーは保存される
OK: 本文で [T1 エネルギー保存則] と書き、ファイル末尾に
    [T1 エネルギー保存則]: theorems.md#t1-エネルギー保存則 を定義する shortcut reference 形式
```

引用（`>` 行）・コードブロック・インラインコード内は対象外。

## 4. 命題セクションの構造

### 4.1 公理（E/I）・定理（T）

**公理（E/I）は概念単位の公理群**として、次の順序で書く。

1. **リード文**（必須）— 見出し直下に**無ラベル**で 1〜2 文。群の要約であり、
   それ自体は規範を持たない（規範は「公理」リストが担う）
2. **公理**（必須）— 番号付きリスト。各項目は原則 1〜2 文の独立した根本前提。
   番号は読みやすさのための連番で、本文からの参照に使わない（参照は ID 単位）。
   `**公理**` の見出しから README の凡例節へリンクする
3. **役割セクション**（任意）— **定義** → **観測事実** → **目安** → **補足** →
   **空白** の固定順で、該当する役割だけを `**役割名**:` として置く。
   セクション内の箇条の先頭には必要に応じて `**見出し語**:`（定義では用語名）を置く
4. **関連**（必須）

公理リストの書き方:

- 項目は**仮定そのもの**だけを述べる。仮定から導ける帰結は **補足** へ、
  例外・傾向の観測は **観測事実** へ、未解明への言及は **空白** へ移す。
  誤読を防ぐ適用範囲の限定（スコープ注記）は項目内の括弧で残してよい
- 同じ主題の複数の仮定は 1 項目に束ねてよい。「片方だけを変える派生作品の
  改変が自然に想像できる」仮定は別項目に分ける
- 「通常」「原則として」等のヘッジ語は、例外の行き先（観測事実・空白・定理）が
  辿れる場合にのみ使う。行き先がなければ言い切る
- 役割セクションの **定義** で定める属性語を項目内で使う場合、初出時に括弧で
  最小の意味を添える（例: 「真度（マナとの共鳴のしやすさ）」）
- **空白** の箇条は対応する未解明領域（Q）へのリンクを必ず伴う

**定理（T）は単一の導出命題**として、次の順序で書く。`**命題**` `**導出元**`
`**関連**` は必須。

1. **命題**（必須）— 1〜2 文で簡潔に何が成立するか
2. **導出元**（必須）— どの公理群・定理から導かれるか
3. **証明スケッチ**（任意）
4. **詳細**（任意）— 命題・導出元から導かれる内容のみ。「公理」リストは置かない
5. **観測事実**・**空白**（任意）— 該当があれば固定順のセクションとして分離する
6. **重要な帰結**（任意。節として書き、独立 ID は付けない）
7. **関連**（必須）— 他命題・応用ファイルへのリンク

```markdown
### [T1] エネルギー保存則

**命題**: 系全体のエネルギー総量は保存される。

**導出元**: [E1 現界](#e1-現界), [E2 真界](#e2-真界), [I1 変換則](#i1-変換則)

**詳細**:
- 物理エネルギー・マナ・精神エネルギーは [I1 変換則](#i1-変換則) により互いに変換可能
- ...

**関連**:
- → [T2 ビッグバン](#t2-ビッグバン), [magic.md](../magic.md)
```

役割セクションの語彙は **定義** / **観測事実** / **目安** / **補足** / **空白** の
5 種のみ（概念的な土台は [`architecture.md` §4.10](architecture.md#410-詳細内の役割ラベル)）。
未解明領域（Q）は対象外。応用ファイルは任意（用いる場合は同じ語彙に従う）。
1 箇条 1 役割とし、複数の役割が混在する箇条は分割する。入れ子の箇条は属する
セクションの役割を引き継ぐ。

### 4.2 未解明領域（Q）

次の 4 ラベルを必ず含める。

```markdown
### [Q1] 真度を人為的に深くする方法

**背景**: 既知の事実と未解明部分の境界。
**現在判明していること**: 観測事実、関連組織の認知レベル。
**この空白の意図**: 物語ギミック・派生作品での活用例。
**関連**: [T3 マナ濃度](theorems.md#t3-マナ濃度), [dungeon.md](../dungeon.md)
```

## 5. ID と分類

- **接頭辞**: `E`（存在公理）/ `I`（相互作用公理）/ `T`（定理）/ `Q`（未解明領域）
- E/I の ID は概念単位の**公理群**を指す。群内の公理の番号は ID ではなく、
  本文からの参照に使わない（NG: 「E5 の公理 3 により…」）
- **採番**: 各分類で末尾連番（`E7`, `I5`, `T10`, `Q7` ...）
- **見出し書式**: `### [E1] 名称`
- 同一ファイル内で **同じ ID を 2 回使わない**
- 廃止された ID は **再利用しない**。`[廃止] T3 旧名称 — 移動先` の痕跡を残す
- 命題が肥大化したら分割記号（`E3a`, `E3b`）を使わず **新 ID を採番** し旧 ID を
  廃止扱いにする
- 定理内「重要な帰結」節および応用ファイル内の節は **独立 ID を持たない**

## 6. 用語集

`world/core/` で定義した全 ID は `glossary.md` に登場させる。新しく命題を
追加したら `glossary.md` にも 1 行追加する。

## 7. 禁止語と廃止コード

本文（引用・コードブロックを除く）に次を書かない。

- **「補題」** — 数学用語。中学生〜の読者を想定した本作では使わない
- **「波長」** — 旧用語。真度（マナとの共鳴のしやすさ）と位相（個体間の適合。かみくだき「チャンネル」）に分離して廃止。旧称として言及する場合はインラインコードで書く
- **`L#` 接頭辞** — 旧「補題」コード（廃止）
- **`C#` 接頭辞** — 旧「系」コード（廃止）

「体系」「系統」のような通常の複合語、ダンジョン分類の `C-1` `C-2` のような
ハイフン区切り表記は対象外（区別される）。

## 8. パス

次の旧パスにリンクしない。再構築前のファイル名・ディレクトリ構造の名残。

```
世界の法則.md   魔法.md   魔術.md   超能力.md   種族.md
/dungeon.md     character/   history/
```

新パスは `world/` 配下・英字名（例: `magic.md`, `spellcraft.md`, `dungeons.md`,
`psionics.md`, `races.md`, `artifacts.md`）。最終形は
[`architecture.md` §3 ディレクトリ構成](architecture.md#3-ディレクトリ構成) を参照。

## 9. 分量上限

執筆の暴走防止のための上限。

| 対象 | 上限 |
|---|---:|
| 命題（`**命題**` 直後）の文数（定理） | **2 文** |
| 見出しレベル | **H4** まで |
| 連続するリスト項目 | **12 項目** |
| 応用ファイル全体の行数 | **400 行** |
| 1 命題エントリの本文字数（リンク部分を除く）— 定理・応用 | **1500 字** |
| 1 公理群エントリの本文字数（同上）— 警告 1500 字＝グルーピング見直しのシグナル | **2000 字** |

意図的に超過させる場合は §11 の例外コメントを使う。
公理群の字数は命題分割ではなく**グルーピング見直し**（概念の切り出し）を
検討するシグナルである（`architecture.md` §4.1）。

## 10. ToDo の集約

書きかけ・課題は **ファイル末尾の `## ToDo` 節** にまとめる。本文中に
`TODO:` / `FIXME:` / `- [ ]` を散在させない。

```markdown
## ToDo

- [ ] [Q3 マナ濃度](core/open-questions.md#q3-マナ濃度) の閾値を数値化
- [ ] artifacts.md との相互リンク見直し
```

## 11. 例外コメント

分量上限（§9）を意図的に超えたい場合、対象の **直前** に次のコメントを置く。

```markdown
<!-- check:length-exempt 列挙網羅が目的のため -->
- 項目 1
- 項目 2
- ... 16 項目続く
```

- 直後の **非空ブロック**（空行で挟まれた最初の塊）の分量上限が解除される
- 解除されるのは分量のみ。リンク切れ・必須セクション欠落・禁止語・旧パスは
  例外コメントでは免除されない
- 禁止語・旧パスを文書例として本文に含めたい場合は、引用（`>`）または
  コードブロックの中に入れる
